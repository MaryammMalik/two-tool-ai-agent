# Two-Tool AI Agent

A small **AI agent** that takes a natural-language goal, plans with an LLM, and completes it by calling tools — inside a hard step limit, with every tool call logged.

> Elevvo Internship — Python Programming & AI Track · **Task 9: AI Agent for a Two-Tool Task** (self-study)

## What it does

Give the agent a goal in plain words:

```bash
python -m agent "What's 15% of 240, and save the answer to a file called result.txt?"
```

The agent loops — *plan → call a tool → observe the result → plan again* — until the goal is done:

1. `calculator` with `240 * 15 / 100` → `36`
2. `file_writer` saves `36` to `result.txt`
3. The agent reports back: **"Calculated 36 and saved it to result.txt."**

## The tools (exactly two, plus a bonus third)

| Tool | What it does |
|---|---|
| `calculator` | Evaluates arithmetic **safely** — parsed with `ast`, only numbers and operators allowed, never `eval()` |
| `file_writer` | Saves text to a file inside a sandboxed `output/` folder (file names are stripped of any directory parts, so it can't write elsewhere) |
| `web_search` *(bonus)* | Short factual lookups via the free DuckDuckGo Instant Answers API |

## Guarantees built into the loop

- **Max 5 steps.** The loop is hard-capped (configurable with `--max-steps`); a planner that keeps calling tools is stopped and the run is reported as incomplete.
- **Actions-only logging.** Every tool call and its result is logged with inputs and outputs — and *nothing else*. The planner's internal reasoning is never requested and never logged.
- **Tool failures don't crash the agent.** An error becomes the tool's result, gets logged, and the planner can react to it.
- **LLM-call counter (bonus).** Every run reports how many LLM calls it took.

### The planner

- With `OPENAI_API_KEY` set: a real LLM (OpenAI function calling, the Module 8 pattern) decides each step.
- Without a key: a deterministic **offline scripted planner** handles the goal shapes above, so the loop, tools, logging and step limit can be run and tested end to end with zero setup. The run output always names which planner was used.

## Features

- Natural-language goals → multi-step tool use
- Safe AST-based calculator (division-by-zero and code injection rejected)
- Sandboxed file writer
- Structured run result: steps used, LLM calls, full tool-call records
- A real logged run in `examples/sample_run.log`
- 11 pytest tests, including a looping-planner test that proves the step cap

## Tech stack

- Python 3.10+ (standard library: `ast`, `logging`, `argparse`, `dataclasses`)
- `openai` — LLM planner when a key is configured
- `requests` — the web-search tool
- `python-dotenv` — loading the key from `.env`
- `pytest` — tests

## Setup

```bash
git clone https://github.com/MaryammMalik/two-tool-ai-agent.git
cd two-tool-ai-agent
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Optional: enable the LLM planner

```bash
cp .env.example .env
# OPENAI_API_KEY=your_openai_api_key_here
```

## How to run

```bash
# The brief's example workflow
python -m agent "What's 15% of 240, and save the answer to a file called result.txt?"

# Bonus tool
python -m agent "Search for France"

# Save the run's log to a file, custom step cap
python -m agent "Calculate 12 * 8 + 5" --log-file run.log --max-steps 3
```

## What I learned

- How an agent differs from a chatbot: a loop of *decide → act → observe*, where the model only ever chooses the next action.
- Why the step limit matters — an agent without one can loop (and bill) forever, and why the limit belongs in the loop code, not in a prompt.
- That logging **actions** (tool, inputs, outputs) gives you a full audit trail without recording chain-of-thought.
- How dangerous "helpful" tools can be: a calculator built on `eval()` is remote code execution, and a file writer without a sandbox is a path-traversal hole — both fixed by design here.
